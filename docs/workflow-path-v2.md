# Pure workflow path comparison

`src/server/github-workflow-path-v2.mjs` exports `assertGitHubWorkflowPathV2(observation, expected): void`; adjacent `.d.mts` declares `WorkflowPathPolicyV2` and `WorkflowPathObservationV2`. This implements the accepted [parent contract](../../docs/architecture-source-path-proposal.md). It accepts structured arguments only, adds no dependency and does not parse provider responses.

The policy selects exactly one run/attempt form: `bare`, `relative-main` (`workflow_path@main`), or `repository-main` (`repository_full_name/workflow_path@main`). Metadata always compares the bare workflow path. Run/attempt also compare `head_branch` to `main` and the canonical lowercase 40-hex `head_sha` to policy `source_sha`. No normalization, suffix stripping or fallback occurs.

Both objects require exact own enumerable data properties on plain or null-prototype objects. Descriptor snapshots avoid reading getters; accessors, symbols, unknown/missing properties and malformed strings are invalid. Strings have a code-unit guard followed by an inclusive 65,534 UTF-8 byte bound. The complete selected run path, including prefix/suffix, must fit that bound on every call, including metadata. The implementation checks component byte sums before concatenation. Structural/policy validation completes before equality comparisons.

Errors contain only the stable message/code `invalid_github_workflow_path_v2` (invalid structure, policy, SHA or size) or `github_workflow_path_v2_mismatch` (valid bounded observation differs). Empty own-present path/branch strings are mismatches with a valid policy; empty SHA is invalid. Errors retain no raw input or cause. Success returns void and means only structural equality with the supplied argument, never authenticated origin, source approval or enrollment.

Developer checks: `node --test tests/github-workflow-path-v2.test.mjs` and `npm test`. Synthetic fixtures cover all forms/endpoints, exact and over-limit composed policies (including metadata), UTF-8 bounds, descriptor safety, precedence, preservation and legacy suffixed-path rejection. Existing six-field decoder and tests are unchanged. No composite decoder, browser/vendor export, database, network, credentials or operational configuration is added. Actual provider compatibility remains an unverified rollout gate; later observer/source/claim/deploy interfaces require separate acceptance and security review.
